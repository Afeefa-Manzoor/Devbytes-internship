# Task 8: Deploy ML Model as REST API

Packages a trained classifier inside a FastAPI service with a validated
prediction endpoint.

## Dataset & Model
- **Dataset:** sklearn built-in Breast Cancer Wisconsin dataset (no download/path dependency)
- **Model:** `StandardScaler` + `RandomForestClassifier` in a single `sklearn.Pipeline`
- **Test accuracy:** ~95.6%

## Files
| File | Purpose |
|---|---|
| `train_model.py` | Loads data, trains the pipeline, validates it, saves `model.joblib` + `model_metadata.json` |
| `main.py` | FastAPI app — loads the saved model at startup and exposes the endpoints below |
| `test_api.py` | Automated smoke tests (`FastAPI TestClient`, no server needed) |
| `requirements.txt` | Dependencies |
| `model.joblib` | Trained pipeline (generated by `train_model.py`) |
| `model_metadata.json` | Feature names/order, target names, accuracy (generated by `train_model.py`) |

## Endpoints
| Method | Path | Description |
|---|---|---|
| GET | `/` | Service info |
| GET | `/health` | Model/service status + reported test accuracy |
| GET | `/features` | Exact ordered list of the 30 feature names the model expects |
| POST | `/predict` | Predict class for one sample |

### Request validation (`POST /predict`)
Pydantic enforces, before any model code runs:
- `features` field is required
- Must be a list of exactly 30 numeric values (`min_length`/`max_length`)
- Every value must be a valid float
- No `null`, `NaN`, or `inf` values (custom validator)

Any violation returns **HTTP 422** with a machine-readable description of what failed.

**Example request body:**
```json
{
  "features": [17.99, 10.38, 122.8, 1001.0, 0.1184, 0.2776, 0.3001, 0.1471,
               0.2419, 0.07871, 1.095, 0.9053, 8.589, 153.4, 0.006399,
               0.04904, 0.05373, 0.01587, 0.03003, 0.006193, 25.38, 17.33,
               184.6, 2019.0, 0.1622, 0.6656, 0.7119, 0.2654, 0.4601, 0.1189]
}
```

**Example response:**
```json
{
  "predicted_class": "malignant",
  "predicted_class_index": 0,
  "confidence": 0.95,
  "class_probabilities": {"malignant": 0.95, "benign": 0.05}
}
```

## Running locally
```bash
pip install -r requirements.txt
python train_model.py        # generates model.joblib + model_metadata.json
uvicorn main:app --reload --port 8000
```
Interactive docs (Swagger UI, auto-generated): `http://127.0.0.1:8000/docs`

Quick test with curl:
```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"features": [17.99, 10.38, 122.8, 1001.0, 0.1184, 0.2776, 0.3001, 0.1471, 0.2419, 0.07871, 1.095, 0.9053, 8.589, 153.4, 0.006399, 0.04904, 0.05373, 0.01587, 0.03003, 0.006193, 25.38, 17.33, 184.6, 2019.0, 0.1622, 0.6656, 0.7119, 0.2654, 0.4601, 0.1189]}'
```

Or run the automated smoke tests (no server needed):
```bash
python test_api.py
```

## Design notes
- **Config block:** paths, random state, and split size are centralized constants at the top of `train_model.py` — no hardcoded values scattered through the code.
- **Reusable functions:** `load_data`, `build_pipeline`, `train_model`, `validate_pipeline`, `save_artifacts` (training) and `load_model_artifacts`, `predict` (serving) are each single-purpose and independently testable.
- **Post-load validation:** both the training script and the API assert the model's expected feature count matches the metadata before proceeding, so a mismatched or corrupted model file fails loudly at startup rather than producing silent bad predictions.
- **Model loaded once at startup**, not per-request, for performance.
- **All 5 smoke tests pass** (health, features, valid predict, and three invalid-input cases), confirmed in `test_api.py`.
